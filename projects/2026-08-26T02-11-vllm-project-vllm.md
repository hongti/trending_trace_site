### 📌 Issue 动态
* **#53810 [性能优化提案]**：针对 Model Runner V2 (MRV2) 的流水线并行（PP）提出性能改进，建议优化最后 PP rank 将采样结果回传给非最后 rank 的 CUDA 路径，以缩短耗时使其更接近 T+PP 消耗。

---

### 🔧 PR 动态

**1. 核心缺陷修复**
* **#53818 [CUDA Graph]**：修复 CUDA Graphs 捕获流问题。强制在当前 stream 上捕获，避免因依赖 `torch.cuda.graph()` 内部懒加载创建的流而导致录制错误。
* **#53812 [投机解码]**：修复当投机解码恢复请求时，Padding 导致总 Token 数超过 `max_model_len` 从而引发引擎崩溃的问题。
* **#53808 [多模态]**：修复模态级别的 `mm_processor_kwargs`（如 `videos_kwargs`）被忽略的 Bug，该问题曾导致 Qwen 等模型的编码器缓存预分配不足。

**2. 新特性与性能支持**
* **#53816, #53815, #53814 [ROCm/MLA 系列更新]**：这一系列 PR 使 ROCM_AITER_MLA 能够在 **解码上下文并行（DCP）** 下运行**完整的 CUDA Graphs**。修改了 a2a 后端原先强制降级为 `PIECEWISE` 的逻辑，并针对 gfx950 添加了返回 LSE 的 asm decode 支持，大幅提升 ROCm 平台 MLA 推理性能。
* **#53809 [多模态缓存]**：为多模态处理器缓存新增 **Mooncake-store 后端**。解决了原有 `lru`/`shm` 缓存在进程重启时丢失、跨 API 服务器进程需重复运行 HF 处理器的问题。

**3. 架构重构**
* **#53811 [模型移除]**：移除了原生的 LongCat（Flash Chat, Lite, MTP）实现，按照迁移模式将支持的因果 LM 架构统一路由至 Transformers 建模后端。

**4. 基础设施与 CI**
* **#53817 [XPU/Docker]**：将 Dockerfile 中 UCX 的安装路径从 `/tmp/ucx_install` 移至 `/opt/ucx`，并简化了 NIXL 的安装。
* **#53813 [测试/CI]**：起草了一个多 GPU CI 覆盖率检查工具，用于检测那些接入 CI 但在运行时自我跳过、未实际执行代码路径的测试用例。
